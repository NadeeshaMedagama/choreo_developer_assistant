# URL Registry Enforcement - Preventing Wrong URLs

## Problem Statement

The AI assistant was providing **incorrect/hallucinated GitHub URLs** to users, which leads to:
- 404 errors when users click the links
- Poor user experience
- Loss of trust in the application

## Root Cause Analysis

The previous implementation had these issues:

1. **Blind Trust of wso2-enterprise URLs**: The URL validator was auto-approving ALL `github.com/wso2-enterprise/*` URLs without checking if they actually exist in the registry.

2. **Limited System Prompt Guidance**: The LLM system prompt only included URLs from the RAG context, not the complete registry of valid repos.

3. **No Registry Validation**: URLs generated by the LLM were not validated against the official repository registry.

## Solution Implemented

### 1. Registry Validation in URL Validator

**File:** `backend/services/url_validator.py`

Added a new method `is_url_in_registry()` that validates wso2-enterprise URLs against the official `OFFICIAL_REPOS` registry:

```python
def is_url_in_registry(self, url: str) -> bool:
    """
    Check if a GitHub URL exists in the Choreo repository registry.
    """
    # Extract repo name and check against OFFICIAL_REPOS
    if repo_name in self.choreo_registry.OFFICIAL_REPOS:
        return True
    return False
```

### 2. Strict GitHub URL Validation

Updated `validate_github_repo()` to **always validate wso2-enterprise URLs against the registry**:

```python
async def validate_github_repo(self, url: str, session: ClientSession) -> bool:
    # For wso2-enterprise URLs, ALWAYS check the registry first
    if owner.lower() == 'wso2-enterprise':
        if not self.is_url_in_registry(url):
            logger.warning(f"❌ Rejecting wso2-enterprise URL NOT in registry: {owner}/{repo}")
            return False
        return True
```

Updated `create_repository_context_for_llm()` in `llm_repo_matcher.py` to include:

## Key Changes Summary

| Component | Before | After |
|-----------|--------|-------|
| wso2-enterprise URLs | Auto-approved (trusted blindly) | Validated against registry |
| LLM System Prompt | Only context URLs | Complete registry + context URLs |
| URL Generation | LLM could hallucinate | Registry-enforced only |
| Invalid URL Detection | Basic pattern matching | Registry + pattern matching |
